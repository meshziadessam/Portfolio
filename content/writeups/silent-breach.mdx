## Lab Overview

Silent Breach is a medium-difficulty CyberDefenders Endpoint Forensics lab. Its stated objectives include examining a forensic image, recovering communication artifacts, analyzing malware behavior, and decrypting affected files. The official tool list includes FTK Imager, a text editor, a SQLite viewer, Strings, and CyberChef.

## Executive Summary

A forensic image of a Windows workstation was examined to investigate a suspicious download and subsequent file encryption. The investigation began with the downloaded executable IMF-Info.pdf.exe, which was assessed as malicious using VirusTotal. Browser download artifacts linked the file to Microsoft Edge. Windows Mail application artifacts led to three IP addresses referenced in a message. Static analysis of the executable exposed a dropped, obfuscated PowerShell script; reversing its character order and Base64 decoding revealed encryption logic and a hardcoded password. Two encrypted documents were recovered from the desktop, decrypted, and reviewed to obtain the challenge secret.

## 1. Evidence Acquisition and Initial Triage

The supplied ethanPC.ad1 forensic image was opened using FTK Imager. Relevant files and user-profile artifacts were exported to a local analysis directory. The Downloads folder contained IMF-Info.pdf.exe, an executable using a PDF-like name. The double extension made it a high-priority triage candidate.

The file MD5 was calculated with PowerShell and submitted to VirusTotal for reputation analysis. VirusTotal flagged the sample as malicious. This reputation result was treated as a triage signal, not as a substitute for behavioral analysis.

```powershell
Get-FileHash .\IMF-Info.pdf.exe -Algorithm MD5
```

## 2. Browser History and Download Attribution

The investigator examined Chrome and Edge user-profile artifacts. The Chrome History database did not yield the relevant download. The Edge History SQLite database, opened in DB Browser for SQLite, contained a downloads table with a target_path entry for IMF-Info.pdf.exe under C:\Users\ethan\Downloads. Related entries for IMF-Secret.pdf and IMF-Mission.pdf were also visible.

The download-source URL was determined from the Edge download record during the investigation. The exact URL is not reproduced here because it is not legible in the supplied screenshot; the screenshot directly establishes the download record and application attribution.

`AppData\Local\Microsoft\Edge\User Data\Default\History`

## 3. Windows Mail Artifact Examination

The challenge next asked for three server IP addresses referenced in an email. An initial search suggested Windows Mail artifacts, so the NTUSER.DAT registry hive was inspected with RegRipper. The app identifier microsoft.windowscommunicationsapps_8wekyb3d8bbwe!microsoft.windowslive.mail provided a lead to the corresponding Windows Communications Apps package.

A file-system search for the package directory identified the application LocalState data and the HxStore.hxd database. Strings extracted from HxStore.hxd exposed the IP addresses and surrounding message fragments.

## 4. Malicious Executable and Payload Discovery

To determine the encryption password, the investigator returned to the suspicious executable and reviewed its VirusTotal behavior details. The report showed a dropped PowerShell script named Gz3m6mG3j2TyAqF2Zx4v.ps1. Searching the executable’s extracted content for that filename exposed script content and Node.js execution-related strings.

The executable contained a packaged Node.js application referencing C:\snapshot\pysever\main.js, along with functions and strings consistent with writing a temporary PowerShell script, invoking powershell.exe, and removing the temporary file.

### 4.1 Identifying the obfuscation

Static inspection showed that the payload reversed and Base64-decoded an embedded string before attempting to execute the decoded script.

The correct analysis sequence was therefore: reverse the encoded text → Base64 decode → UTF-8 decode → inspect the resulting PowerShell. The decoded content was treated as potentially harmful and analyzed without running its execution routine.

## 5. Encryption Logic and Hardcoded Password

Inspection of the deobfuscated script revealed a predefined password and AES encryption functionality. The recovered password was:

`Imf!nfo#2025Sec$`

| Parameter | Recovered value |
| --- | --- |
| Cipher | AES-256-CBC |
| Padding | PKCS7 |
| Password | Imf!nfo#2025Sec$ |
| Key derivation | PBKDF2-HMAC-SHA1 |
| Iterations | 10,000 |
| Salt | 01 02 03 04 05 06 07 08 |

The significance of the hardcoded password is that an analyst who recovers the key-derivation parameters can reproduce the decryption operation. This is not an AES weakness; it is a consequence of exposing the secret and cryptographic configuration in recoverable malware code.

## 6. Recovery of Encrypted Documents

Two affected files were located on the desktop and exported from the forensic image: IMF-Secret.enc and IMF-Mission.enc. The analyst used the recovered password and the script’s encryption parameters to reverse the AES operation. The first decrypted document, IMF-Secret, did not contain the requested flag. The second, IMF-Mission, was restored to a readable PDF and contained the secret string at the bottom of the document.

The process was performed on exported copies of the evidence. The decryption script must use the original algorithm, key derivation, IV handling, and padding rules; simply changing the file extension would not restore the PDFs.

## 7. Final Answer and Investigation Outcome

`CyberDefenders{N3v3r_eX3cuTe_F!l3$_dOwnL0ded_fr0m_M@lic10u5_$erV3r}`

The secret string was found in the recovered IMF-Mission PDF. The case demonstrates a complete forensic chain: image examination, executable hashing and reputation checking, browser-download attribution, application artifact recovery, static payload deobfuscation, cryptographic analysis, and restoration of affected files.

## 8. Key Findings and Analyst Notes

• The executable name IMF-Info.pdf.exe disguised an executable as a PDF-like download.
• Edge’s SQLite History database provided the decisive download evidence.
• The Windows Mail package identifier in NTUSER.DAT was a pivot to HxStore.hxd, not the email message itself.
• The PowerShell payload used character reversal plus Base64 encoding, followed by Invoke-Expression.
• Recovery was possible because the encryption password and derivation settings were embedded in the script.
• VirusTotal findings and challenge hints were supporting leads; local artifacts supplied the primary forensic evidence.
